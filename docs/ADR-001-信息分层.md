# ADR-001：信息分成「档案」「行情」「判断」三层

## 状态

已采纳。**日期：** 2026-09-08 **决定人：** Sasha、Claude

## 背景

网站上的信息来源和变化速度差别很大：建成年份十年不变，挂牌价一周就变，"安静程度"是我们的主观判断。之前只分"固定信息"和"实时信息"两类，已经拆成 `condos.json` 和 `prices.json` 两个文件，但页面上看不出区别，主观判断也混在固定信息里。Sasha 的要求是：读者和管理员都要能明确知道哪些信息可以百分百放心，哪些可能有误差、为什么。

## 决定

我们把所有数据分成三层，每层有固定的中文名、英文标识、来源、更新方式和页面标记：

| 层 | 英文标识 | 一句话 | 更新 | 页面标记 |
|---|---|---|---|---|
| 档案 | `profile` | 不会变或很少变的事实，来自一手来源，人工审核后发布 | 采集流水线 + 人审，每 30–45 天复核 | 绿色实心点，「档案 · 核实于 日期」 |
| 行情 | `market` | 随市场变的挂牌数字，机器抓取 | 每 12 小时自动 | 琥珀色实心点，「行情 · 抓取于 时间」；超过 36 小时未更新显示「已 X 小时未更新」 |
| 判断 | `judgment` | 我们的估算或主观评价 | 人工，随复核更新 | 灰色空心点，「判断」 |

文件与字段约定：

- `data/condos.json`：档案。每条记录新增 `judgment` 子对象（迁入 `daily`、`quiet`，以及 `transit.walk_est` 为真的步行分钟），和 `provenance` 对象：`{ 字段名: { source, at, method } }`，`method` 取 `auto`（脚本采集）、`manual`（人工查证）、`field`（实地）。整条记录保留 `verified_at`。
- `data/prices.json`：行情。保持现有结构，`updated_myt` 是唯一的时间戳。
- 页面：三层标记由同一个渲染函数产生，任何数据块都必须经过它，不允许裸数字。
- 文案：只用「档案 / 行情 / 判断」三个词，导航、卡片、说明、后台一致。

## 后果

### 好处

- 读者一眼分清能信多少；管理员一眼知道该复核什么。
- 主观判断从事实里剥离，"先想清楚"的打分可以明确标"粗略"。
- provenance 让每个数字可追溯，也是防盗用的证据链的一部分。

### 代价

- `condos.json` 每条记录变长，人工编辑时要维护 provenance；靠流水线自动填，减少手工。
- 页面上标记变多，需要克制的视觉设计，否则显得杂。

### 中性

- 两层变三层不改变现有的自动刷新流程。
- 判断类字段以后可以逐个"升级"为档案（比如实测步行时间后从判断变为档案）。

## 备选方案

- **只分两层（固定 / 实时）**：主观判断混在固定信息里，读者会把"安静程度 4 分"当事实。否决。
- **每个字段单独带层级标签**：最精确，但数据文件和渲染都复杂一倍。改为按文件和子对象归层，字段级只记来源。
